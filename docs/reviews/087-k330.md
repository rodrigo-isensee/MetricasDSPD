## Como o dono deve ler o número
A amostra segue a decisão 4a ("uma página de worklogs"). Ela responde à pergunta do D1, se a API entrega o `comment`, mas não mede de novo os 40%.

- **`comComentario` > 0:** a API entrega o comentário. Confira 2 ou 3 apontamentos com texto no BusinessMap, como a decisão pede. Se baterem, os 40% (6334 de 15826 apontamentos, contados por lançamento, a mesma unidade do comando) podem ser lidos como retrato do preenchimento.
- **`comComentario` = 0 com `total` > 0:** não conclua nada. Nesse caso o comando não separa "a chave não veio" de "a chave veio vazia" (A1), e a pergunta volta ao time.
- **`total` = 0:** os cards ativos lidos não tinham lançamento. A amostra está vazia e não responde à pergunta.
- **A proporção `semComentario / total` não é a dos 40%.** A população é outra: só cards ativos, os 200 primeiros da ordem da API, sem filtro de data e uma página de até 1000 lançamentos. Os 40% vêm da base inteira, com cards arquivados, e a base trata como vazio também o comentário só de pontuação. Use a proporção só como sinal de ordem de grandeza. Não precisa de mais páginas para responder à pergunta do D1. Para medir os 40% de novo, seria preciso outro pedido.
