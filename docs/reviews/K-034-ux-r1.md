## Médio
- M-1 Selo-falha (Operacional 1280): a captura "selo de falha" mostra só "Não foi possível verificar a coleta. [Tentar de novo]" em vermelho. Isso é falha de leitura do estado de coleta, não "Falha de coleta" (W5, CA-09). Falta o selo Falha com ícone e texto e o aviso "Coleta falhou em {data}. Mostrando dados de {data}.". Além disso, sem "Atualizado em" (CA-01), "Fonte" fica só no canto. Correção: separar os dois estados. Falha de leitura da API usa linguagem neutra e mantém "Tentar de novo". Falha de coleta usa selo Falha mais aviso mais dados anteriores. Confirmar com QA que o modo `coleta-erro` mostra o segundo. Se a captura for dele, ela não evidencia o CA-09.
- M-2 "Pede atenção" preso em "Verificando o que pede atenção..." nas capturas de Sustentação e Operacional, enquanto o resto da página já carregou (cartão com esqueleto gigante). Se for captura precoce, tudo bem. Se persistir, é falha de status (Nielsen 1). Para a decisão do front de "omitir e avisar" valer (CA-05), o aviso precisa estar visível quando algum item foi omitido, p. ex. "Metas em calibração não entram nesta lista". Não consegui conferir isso nas capturas: a QA deve anexar uma captura com o aviso visível.
- M-3 Faixa de calibração (Sustentação): a janela aparece como "15/09 a 13/11/2026", enquanto a spec e o protótipo usam 14/11 (e a /dados mostra a janela vigente por fonte). Se a fonte é a mesma, as duas telas divergem. Verificar se é só dado de exemplo. O link "Saiba mais" não diz para onde vai. Correção: "Saiba mais sobre a calibração" levando a `/dados?fonte=ac`.

- B-2 /dados: o selo "Falha" ao lado de "Última coleta ok: 08/10" é correto, mas a leitura "Falha" mais "Última tentativa: falha" é redundante. Aceitável; manter o selo e remover o "falha" da frase seria mais limpo.
