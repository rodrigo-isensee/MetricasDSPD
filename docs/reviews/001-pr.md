Entregar os painéis do MetricasDSPD (FL1 operacional, FL2 tático, FL3 estratégico, Sustentação, Espera invisível e Visão geral) funcionando sobre uma base mock determinística, para validar leitura, regras de cálculo e experiência antes da coleta real (WS2/WS5). ## O que mudou
- **Painéis (`web/`)**: React + Vite com rotas por nível (Visão geral, Operacional diária e semanal, Tático, Estratégico, Sustentação, Espera invisível, Ajuda); barra de filtros com estado na URL; estados carregando, vazio, erro e "amostra insuficiente" (< 20 itens não publica estatística); tema claro e escuro; layout responsivo até 320 px; gráficos em chunk separado.
- **Biblioteca de cálculo (`packages/metricas`)**: tempo em dias úteis, percentis 50/85/95 em janela móvel de 12 semanas, Monte Carlo, saldo acumulado, índice de espera; matriz `REGRAS_METRICA` com seis propriedades por métrica e meta-teste bloqueante (nenhuma métrica com cálculo próprio, BusinessMap e Acelerato nunca misturados, story/frente/projeto nunca no mesmo histograma).
- **Contratos (`packages/contratos`)**: tipos e schemas zod compartilhados.
- **Mock (`packages/mock`)**: gerador determinístico por semente, separado por origem (BusinessMap e Acelerato), com hash da base para reprodutibilidade.
- **Monorepo**: npm workspaces (`packages/*`, `web`, `e2e`), ESLint + Prettier na raiz, script `npm run pronto` (lint, formatação, typecheck, unitários, build e orçamento de bundle), verificação de fronteiras entre pacotes.
- **E2E (`e2e/`)**: Playwright (shell, filtros, estados, responsivo, acessibilidade com axe, perf), Lighthouse por rota, gate de QA.
- **Processo**: hook `pre-push` que recusa envio para a `main`; pareceres de code review em `docs/reviews/`, QA em `docs/qa/`, quadro Kanban e retrospectivas.
