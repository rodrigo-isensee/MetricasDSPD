# Contrato da métrica O23

Propósito: descrever o O23 (estoque parado dentro do WIP), que não é uma métrica com rota própria: é o bloco `parados` do resultado do O2. Público: time (back-end, front-end, QA). Revisão: 2026-10-29.

Esta página é escrita à mão a partir do código e dos testes. Ela não é gerada por `pnpm run docs:gerar` (o gerador cobre só os ids de `METRICA_IDS`, e o O23 não tem id). O contrato executável é o do O2: [O2.md](O2.md), campo `parados`, e a fotografia [`../snapshots/resultados/O2.json`](../snapshots/resultados/O2.json).

## Rota

Não há rota do O23. O bloco vem em `GET /api/v1/metricas/O2` (erros, cabeçalhos e cache: [http.md](../http.md)), junto do resto do resultado do O2.

## Filtros

Os do O2: equipe, tipo, sistema e período (parâmetros em [O2.md](O2.md)). Com exatamente uma equipe, a quebra por etapa usa as colunas do quadro dela; sem equipe ou com várias, usa "Fila" e "Execução".

## Regras de cálculo

| Campo | Valor |
|---|---|
| Domínio | businessmap |
| Granularidade | story |
| Código | `calcularO2` em `packages/metricas/src/businessmap/o2.ts` |
| Entrada | `semMoverHaDiasUteis` de cada item do WIP, já calculado pelo O2 |
| O que é "mover" | só a mudança de coluna; tempo apontado nunca conta como movimento (briefing, seção 7.1) |
| Parado | `semMoverHaDiasUteis` maior que `LIMITE_PARADO_DIAS_UTEIS` (5 dias úteis), comparado com o valor já arredondado do item. "Parado há mais de uma semana" = mais de 5 dias úteis, por decisão do dono de 2026-10-29 |
| Parado e bloqueado | item parado que está bloqueado conta como parado (o bloqueio não altera `semMoverHaDiasUteis`), por decisão do dono de 2026-10-29; o motivo do bloqueio segue na lista |
| Limite | constante única em `packages/metricas/src/core/criterios.ts`; mudar o valor exige nova `VersaoCriterio` no mesmo commit (T2.6) |
| Versão do critério | `VERSAO_CRITERIO_PARADOS_V1` (`criterio-2026-10-14-parados-v1`, data 2026-10-14, `afeta: ['O2']`); vira marcação do O2 quando o período a cruza, sem repetir id |
| Base do percentual | itens em andamento (WIP atual), `n` = quantidade de itens do WIP |
| Mínimo de amostra | 20 itens em andamento: abaixo, só "k de n" (`status: 'insuficiente'`, sem `pct`); com 20 ou mais, `status: 'ok'` com `pct` |
| Quebra | `porEtapa`: `k` de parados em cada etapa, na mesma lista de etapas do O2 (com uma equipe, item iniciado que voltou a uma coluna fora das etapas do O2, isto é, fora de trabalho e homologação, fica fora de `porEtapa`; por isso a soma dos `k` pode ficar abaixo do `k` da taxa) |
| Sem itens em andamento | `k: 0`, `n: 0`, `status: 'insuficiente'` |
| Status | ok |

## Schema do resultado

Definido em `paradosSchema` (`packages/contratos/src/tambem.ts`), obrigatório em `ResultadoO2`:

```json
{
  "parados": {
    "limiteDiasUteis": 5,
    "taxa": {"status":"ok","k":5,"n":20,"pct":25},
    "porEtapa": [{"etapa":"Fila","k":2},{"etapa":"Execução","k":3}]
  }
}
```

Quando `n` < 20: `"taxa": {"status":"insuficiente","k":1,"n":3,"minimo":20}`. Exemplo ilustrativo montado a partir dos casos do teste, não é uma resposta capturada da API.

## Cartões que usam a métrica

- Painel `operacional`, seção de visão diária: bloco dentro do cartão do O2 (U-2: bloco, não cartão). O bloco O23 está em `web/src/features/operacional/components/CartaoO2.tsx` (função `BlocoParados`, com `data-testid` `o23-parados`, dentro do cartão do O2) e é testado em `web/src/features/complementares/operacionais.test.tsx` (linha 623). O código não mostra se o `o23` tem entrada própria em algum catálogo ou na Ajuda: lacuna, não inferida.

## Testes

`packages/metricas/src/businessmap/o23.test.ts`: constante e versão v1; marcação no período; abaixo de 20 itens devolve "k de n"; com 20 itens publica `pct` (5 de 20 = 25%) e quebra por coluna com uma equipe; sem itens, 0 de 0; no mock, o percentual fica entre 20% e 30%.

## Lacunas

- Texto da leitura na tela ("7 de 31 itens ... sem mover há mais de 5 dias úteis") é da especificação de UX, não do contrato.
